# 部署步骤

前置：确认现役插件目录状态，避免覆盖既有插件。

```bash
HERMES_HOME="<你的 Hermes home，例如 ~/AppData/Local/hermes 或 ~/.hermes>"
ls "$HERMES_HOME/plugins/"     # 先看清楚现役插件，避免覆盖
```

## 1. 复制插件包

```bash
SRC="<本仓库>/package/fragile-prompt-enhance"
DST="$HERMES_HOME/plugins/fragile-prompt-enhance"

# 目标已存在时停止，禁止删除或覆盖未知内容。
test ! -e "$DST" && cp -r "$SRC" "$DST"
```

复制后确认布局（三者缺一不可）：

```bash
ls "$DST"                       # plugin.yaml  NOTICE  __init__.py  fpe_core.py  fpe_templates.py  dashboard/  desktop/
ls "$DST/dashboard"             # manifest.json  plugin_api.py  entry.js
ls "$DST/desktop"               # plugin.js  NOTICE
```

`fpe_templates.py` 是模板归档格式（导入/导出/校验）那一层，由 `dashboard/plugin_api.py`
按**文件路径**加载（`_load_sibling`，与 `fpe_core.py` 同一套做法：不把插件目录塞进
`sys.path`）。少复制它，后端会在导入期直接报错，**不会**静默降级成「不校验」。

三种形态的分工（已核对真实源码）：

| 部件 | 位置 | 加载方 | 依据 |
| --- | --- | --- | --- |
| agent 半 | `plugin.yaml` + `__init__.py` | 插件管理器，`register_fn = getattr(module, "register", None)` | `hermes_cli/plugins_loader.py` |
| dashboard 后端 | `dashboard/manifest.json` (`api: plugin_api.py`) + `plugin_api.py` 的 `router` | web server，挂到 `/api/plugins/<name>/` | `hermes_cli/web_server_dashboard.py` |
| desktop 前端 | `desktop/plugin.js` | 桌面插件系统；统一包里的 desktop 半会被**复制**到 `<HERMES_HOME>/desktop-plugins/<name>/` 并写入 `.hermes-package.json` 标记 | `apps/desktop/electron/desktop-plugins-root.ts` |

## 2. 启用插件（必需）

后端 `api` 只在插件被启用时才导入。`_plugin_api_mount_skip_reason`：`source == "user"` 时必须出现在 `plugins.enabled` 里，否则跳过挂载。

在 `config.yaml` 中保留现有 `plugins.enabled`（尤其 scope-recall），仅追加本插件；下面是新增字段示意，不是整段替换配置。先备份原配置，使用现役官方写入机制，精确授权所选模型和供应商，不默认授予通配范围：

```yaml
plugins:
  enabled:
    - fragile-prompt-enhance
  entries:
    fragile-prompt-enhance:
      # 可选：授权独立增强模型。不给也能用（跟随会话模型）。
      llm:
        allow_model_override: true
        # allow_provider_override: true
        # allowed_models: ["*"]
        # allowed_providers: ["*"]
```

**不要**同时把它放进 `plugins.disabled`。

## 3. 重启并验证

```bash
hermes --version
hermes plugins list                 # 应列出 fragile-prompt-enhance 且无 error
```

启动 Hermes Desktop 后：

1. 输入框内出现 split 按钮（主键=当前模式，右侧箭头=菜单）。
2. 打开菜单 →「设置…」→「关于」：后端绑定应显示 `宿主上下文（ctx.llm）` 而不是「不可用」。若显示「不可用」，说明后端路由未挂载或被跳过（见步骤 2）。
3. 写一段草稿 → 点增强 → 应**只回填**，默认**不**弹出对比视图（设置里可开启「成功后打开对比」）。
   想比较时用菜单里的「对比」手动打开，结果一直在内存里。
4. 点一次增强后立刻再点（停止）→ 不应有任何回填。
5. 若授予了 `allow_model_override`，在设置里选独立模型并确认会话模型未变。

后端可用性可单独探测：

```bash
curl -s "http://127.0.0.1:<port>/api/plugins/fragile-prompt-enhance/status"
```

## 4. 回滚

先在官方插件界面禁用本插件。按本次安装记录撤回新增配置项和插件包及其桌面副本；涉及删除前确认归属并取得必要授权，不执行无条件递归删除。

需要重启 Desktop/Gateway 时先征得用户同意，不自行结束可见进程。

**回滚保留用户数据：不清任何设置、模板或剪贴板。** 这里的「回滚」只指撤回本次新增的配置项与
插件包，**不**包括清除用户数据。插件设置与两套模板存在渲染端 localStorage 的
`hermes.plugin.fragile-prompt-enhance.*` 键里，它们**属于用户**：禁用、卸载、回滚、升级都
**原样保留**，不代删键、不清空值、不替用户「恢复出厂」。

- 想回到出厂模板：请用户自己在「设置 → 模板」点**「恢复默认」**（写当前代默认）
  或**「恢复上一个版本」**（与被换下来的那一对互换，可再换回）。这两条都是可逆的用户动作。
- 想改用别的模板：用「导入」并自己确认预览，或直接在模板编辑器里改。
- 取消「导出到文件…」只是**取消**：不写文件、不改模板、**不动剪贴板**——包括**不**清空剪贴板里
  原有的内容，界面上只说「没有导出」。要复制归档请显式点「复制归档到剪贴板」。

## 已知风险（部署时请留意）

1. **同进程假设**：插件后端在网关进程内运行，`hermes_cli/plugin_events.py` 明确说明
   「在 `hermes serve`（Desktop 后端）下，插件路由、slash 命令与 agent 回合的 tools/hooks 跑在一起」。
   因此 agent 半与本插件的 `plugin_api.py` 共享进程，按文件路径解析 `PLUGIN_CONTEXT` 才能成立。
   若在某个宿主里两者不同进程（例如只用 `hermes plugins validate` 之类仅导入后端的场景），
   `/enhance` 会返回 `503 llm_unavailable` 而**不会**伪造结果——这是预期行为，不是静默降级。
2. **装载顺序**：若后端路由的导入早于 agent 半的 `register(ctx)`，首次调用可能拿到 503；重试即可（`/status` 的 `binding` 会从 `unavailable` 变为 `ctx`）。
3. **dashboard 清单只为挂后端**：`tab.hidden = true`、无 slots，因此不会出现多余标签页；`entry.js` 是 no-op，仅用于避免 `entry` 404。
4. 桌面插件系统的 desktop 半复制行为会把 `desktop/plugin.js` 复制到 `desktop-plugins/`；修改源文件后需要让它重新复制（重启或触发其 mtime 检查）。
