# 测试与验收说明

不安装任何依赖：Python 侧用 stdlib `unittest` + 自建驱动，desktop 侧用 Node 内置 `node:test`。

## 怎么跑

```bash
cd <本仓库根目录>

# Python 半
# 必须用 `hermes --version` 对应的那个安装环境的 venv python，不要用全局 python：
# 测试要导入真实的 Hermes（fastapi/starlette、hermes_cli.*），全局 python 没有它们。
PY="<HERMES_HOME>/installs/<install>/environments/<env>/venv/Scripts/python.exe"
HERMES_REPO="<HERMES_HOME>/hermes-agent" "$PY" tests/run_python_tests.py

# desktop 半
node --test tests/test_plugin_desktop.mjs
```

`<HERMES_HOME>` 就是 `hermes --version` 指向的那套运行时所在的目录（Windows 上通常是
`%LOCALAPPDATA%\hermes`，Linux/macOS 上是 `~/.hermes`）。确认被测运行时：

```bash
"$PY" -m hermes_cli.main --version
```

`HERMES_REPO` 只影响清单类用例（`test_manifests.py` 等）：它们需要导入真实 Hermes 的
`hermes_cli.plugins_manifest` 与 `hermes_cli.web_server_dashboard`。找不到源码时这些用例
**skip 而不是 pass**，避免假装覆盖。

### 1. 内部协议标记泄漏（真实故障）

真实 Kimi 增强稿的末尾把 `===ENHANCED_PROMPT===` 一起带进了要发出去的正文。根因是解析器只
消费了**开头**那个标记：`parse_model_output` 里 `text.split(ENHANCED_MARKER, 1)[1]` 之后，
末尾重复的标记没有任何一步会去掉。

修法（`fpe_core._strip_wrapper_markers`，只在正文两侧、只认**整行**标记）：

- 头部/尾部的标记行成串剥离；标记行允许 `**…**`、`` `…` ``、`#`、结尾冒号等装饰；
- 空白行**不遮挡**包装行（`===SCORES===\n{…}\n===ENHANCED_PROMPT===\n` 这种真实形状里，
  标记在最后一个换行**之前**）——但只有真的剥掉了标记行才会顺带吃掉那些空行；没有标记行时
  空白一个字节都不动；
- **只有在整行且只在两侧**才剥：正文中间提到的 `===ENHANCED_PROMPT===`、内联出现的
  `===END===`、代码围栏里的同名标记都是数据，一律保留；
- 调用方把**草稿**传进来当证据：草稿自己最后一行就是那个标记行时，尾部那一行是作者写的，保留；
- 两侧都只剩标记（没有正文）→ 返回空串，宁可报「没有可用正文」，也不把标记当草稿回填。

另外补了两个同族的漏：`===END===`（或重复标记）跟在**整串代码围栏**后面时，此前会掉进 plain
分支而把 ``` 围栏留在交付物里；现在先剥包装行再判「整串就是一个围栏」，与无标记时的行为一致。

**坏格式仍然不丢正文**：评分块缺失/非法/结构不符时，正文照常返回，只有评分降级
（`score_error` 为 `empty` / `unparseable` / `unrecognized` / `absent`）。

### 2. 模型来源：三种来由，且「请求」永远不是「回执」

截图里专用 DeepSeek 与 Kimi 两次都显示成「全局模型」。根因是结果里只有**通道**（`path`），
没有记录**来由**：专用模型与「还没有活跃会话」两种完全不同的选择都走 profile 全局通道。

- `planRun` 现在同时给 `path`（通道）与 `source`（来由，三值）：`dedicated`（插件设置里固定的
  专用模型）、`session`（跟随当前会话）、`global`（新建/无活跃会话，走全局）；
- `modelAttribution()` 把三类事实**分开**呈现，绝不互相冒充：
  - `requested`：本插件提出的请求（固定模型/供应商）；
  - `receipt`：**只有宿主真的回报了**才存在；`llm.oneshot` 的结果类型是
    `LlmOneshotResult(Result): text: str`（`tui_gateway/contracts/sessions.py`），
    **不带模型名**，所以跟随会话那条通道永远没有回执——界面说的是「这条通道只回正文」，
    而不是编一个模型名；
  - 没有回执时明确写「宿主没有为这次结果回执模型名」，**不把请求里的模型伪称已确认**；
  测试用「同一个名字在整页里出现几次」来锚住这一点。
- 来源不明时不猜：`sourceLabelKey` 只认三个值，其它一律空，界面退回 `—`。

### 3–4. 提示词边界（精准模式允许不改；上下文规则不被误读）

- 精准模式显式允许「**只去重/只整理顺序，甚至保持原样**」——「没有改动」本身就是合格结果；
  并明确禁止为了凑改动而添加评审维度、检查清单、验收标准、评分表或「下一步」。
- 上下文规则写清两件事：增强器自己没有历史、附件、仓库或记忆，**但下游执行者可能有它自己的
  上下文**；因此草稿里的指代（「这个插件」「按刚才方案」）保持原样，不删、不猜含义，
  也不写成「内容附下方」「见附件」这类并不存在的指向；同时**不要停下来要求用户补资料**
  （不编、不叫停、不读历史）。
- 三源中文方法完整保留：WB 分享包的「WHAT not HOW」「未提及技术不添加」、Heybinshao 的
  「语言跟随」「只改写不执行/保持实体名称」、作者本人的「解构 → 重构 → 复核 → 只输出」（含
  「实体」「受众」）；创意模式按草稿给出的**自由度**展开，不改变原意与授权。
  这几条都有专门的措辞断言，防止以后被无意删掉。

### 5. 结果页：已有评分理由 + 可选改动说明

- 评分 JSON 里的 `rationale` 一直在返回，此前**从未渲染**；现在结果页显示两稿的理由（带标签）。
- 新增**同一次调用**内可选返回的 `changes`（模型自述改了什么）：缺失就是 `''`，界面写「本次
  模型没有说明自己改了什么」；缺失/非法/超长都不会丢正文、**不会追加第二次请求**（schema 与解析
  都按可选键处理，`json` 信封与 `===SCORES===` 两种形状都读）。界面明确标注这是模型自述、
  **未经核对**（不是验证过的改动清单）。
- 兼容性：旧的评分块（没有 `changes`、没有 `rationale`）仍然照常解析，`rationale` 缺省为 `''`。

### 6. 原文 ↔ 增强稿的增删高亮

- 新的 `diffDrafts()` 在**行**级别标出增/删，只给符号着色，**文本本身不改一个字节**（代码、路径、
  缩进、空白全保留）；`compareView()` 决定默认视图，超过 `DIFF_LIMITS`（400 行 / 12 万格）
  或渲染行数上限时改为「完整原文」视图，并在界面上说明**为什么**换视图（不静默切换）。
- 用户随时可以在「高亮改动 / 完整原文」之间手动切换。
- **没有安装任何依赖**：LCS 用两行滚动数组 + 回溯，无 DOM diff、无每行 DOM 操作，长文本只算一次。

### 7. 回归补充

## 本轮：模板版本记录（导出 `template_version` 不再为 `null`）（已同步两份安装副本）

收尾轮，两件事：**修掉归档里 `template_version` 为 `null` 的版本记录缺陷**（沿
「初次默认 → 迁移 → 自定义 → 导入 → 恢复 → 导出」整条链），以及**清理开发期生成残留 + 统一文档**。
没有新增功能，没有改动结果页/模板迁移/思考等级那几块已验收的行为。

### 1. 根因：导出读的是「记录」，而不是它即将打包的那串字节

`transferBody()` 原先这样组装导出请求体：

```js
return exportRequestBody(templates, Object.assign({ version: templateMeta().version }, options))
```

`templateMeta().version` 取自 `templates.meta.v1` 这条**记录**。而记录是**书签，不是事实**：

- **初次运行没有记录**：`templates.v1` 都没写过，插件直接服务出厂默认，`meta.version` 是 `null`
  → 导出的归档带上 `"template_version": null`——正是用户遇到的那一份；
- **导入会把归档自己的声明抄进记录**：`commitTemplates(next, { version: preview.version })`
  让一份「内容是默认、却写着 1」的归档把 1 写进记录，之后的导出就照着这个**声明**走；
- 于是「版本」描述的既不是字节，也不是任何事实。

### 2. 修法（四处，`desktop/plugin.js` + 格式层）

- **导出改为从字节推导**：`transferBody()` 不再读记录，直接交给 `exportRequestBody()` 按
  `defaultVersionOf(templates)` 判定——**是**某个已记录的出厂默认就给那个整数，**不是**就给显式
  的 `custom` 标记。`exportRequestBody()` 自己兜底（整数 ≥ 1，否则 `custom`），
  调用方漏传也不会把自己写成 `null`。
- **导入不再抄声明**：`commitTemplates` 的 `version` 一律**从字节推导**（`delete patch.version`），
  归档声称的版本只作为**预览信息**呈现（`statedTemplateVersion()`：整数或 `custom`，其余为 `null`），
  绝不写进记录。
- **记录在首次运行时落定**：新增 `settleTemplateVersion()`，在 `register()` 里、迁移之后调用。
  它**只写记录**（不碰 `templates.v1`、不碰回退槽），且记录与字节一致时不写（不会每次启动都改写）；
  `state` / `source` / `fromVersion` 原样保留，不替内容编造来源。
- **格式层**：`fpe_templates.FORMAT_VERSION` **1 → 2**，新增常量 `CUSTOM_TEMPLATE_VERSION = "custom"`。
  布局 1 仍可读（`LEGACY_FORMAT_VERSIONS = (1,)`），其 `null` 被如实报成
  **未声明版本**（警告 `template_version_unstated` + `older_version`），**不是**错误、**不**冒充某个版本。
  `/templates/export` 的请求模型接受整数或 `custom`，其余（字符串、0、负数、小数、布尔）一律 400
  `invalid_request`。

**语义边界（有意为之）**：安装态记录 `templates.meta.v1` 里的 `version: null` 含义是
「**不是**任何一个已记录的出厂默认」，与 `templateVersionOf()` 的既有语义一致；**归档**这一层
才需要显式的 `custom`——文件必须自己说清它是什么，`null` 在那里是歧义的。所以：**自定义内容
导出为 `"custom"`，旧归档仍按 v1 读入，出厂默认导出为真实整数**。

### 1. 预览必须显示内容差异，而不是只报字数（上一轮不够）

上一轮 `importPreview()` 的每条 `changes` 只有 `currentChars` / `incomingChars`，
界面文案是「mode · field: N → M characters」——**字数相同即可满足**，而用户要决定的恰恰是
「这会把我的文字换成什么」。修法是**复用本来就有的那一个 diff**：

- 新增 `previewFieldDiff(live, incoming)`（导出，便于直接断言）：调用对比视图同一个
  `diffDrafts`，返回 `{ ok, identical, added, removed, rows, shown, changed, truncated, reason, lines }`；
  `rows` 是最多 `PREVIEW_DIFF_ROWS`（8）条**改动行的原文**（`kind: 'add' | 'remove'`），
  只列**改动**行，未改动的行不进列表（列全部就不是差异了）。
- `<ImportPreview>` 在原有的字数行**之后**、对**每个会变的字段**渲染
  `data-fpe="import-diff-<mode>-<field>"`（`data-diff="ok"`）块：`-add` / `-remove` 行带
  `+ ` / `- ` 前缀与改动行原文，`-count` 行给出 `+added / −removed` 的真实行数，
  截断时 `-more` 行明说**还剩几行未列出**。前缀只由渲染端加，**归档字节一个 byte 都不动**。
- **超过 `DIFF_LIMITS`** 的字段：`diff.ok === false`、`reason: 'too-large'`，界面渲染
  `data-diff="too-large"` 并直说「太长，无法在此逐行比较」——**不**退回成只报字数。
- 字段不变（`identical`）时不渲染差异块：没有改动就没有可看的行。
- 4 条新文案进**两个**语言包（`transferImportDiffCount` / `More` / `TooLarge`），
  仍是宿主来的 `translate`，仍是函数式带参文案。

### 1. 结果页：一条短行 + 可展开详情（仍然区分「请求」与「回执」，错误照旧不藏）

主界面原本把三到四行出处说明（通道来解释、请求说明、回执/未回执）连同
`provider · model · ms · mode` 一起堆在标题下面，实际是**说明**挤掉了**状态**。

现在：

- 主界面只有一条 `data-fpe="result-summary"` 短行：**来源标签 · 模型名 · 耗时**。
  来源标签仍是那三个不同的词（专用 / 本会话 / 全局），不合并、不借用。
- **模型名取谁是有规则的**：`modelAttribution().receipt` 是宿主自己回执的作答模型，
  `requested` 只是本插件**请求**的。有回执时短行显示回执名并标 `data-confirmed="true"`；
  没有回执时显示请求名并同时打上 `未确认` 标记、`data-confirmed="false"`——
  请求永远不会出现在回执的位置上。连模型名都拿不到时显示 `无模型名`，不编造。
  这条规则由 `resultSummary()` 这个纯函数决定，用例直接对着它断言。
- 复杂说明（通道解释、`requestedNote`、`receiptNone` / `receiptNotCarried` 以及
  `provider · model · ms · mode` 那行）收进 `data-fpe="result-details"`，
  由一个**真实的** `RowButton` + 宿主自带的 `DisclosureCaret` 开合（`aria-expanded` 同步），
  由 ui 状态 `resultDetails` 驱动，所以一次点击就是用户走的那条路径，也能被用例驱动。
- **错误一律不进详情**：评分失败的原因、精确项缺失的阻断、`写入照旧` 这个出口，
  在折叠状态下全都还在屏幕上——用例 `an error is never moved into the disclosure`
  就是钉这一条，折叠时断言那三段文案与出口按钮仍在。
- 保留原有：全文/差异切换、评分理由、改动说明、精确项面板，以及**唯一滚动区**
  （新加的详情块不带自己的 `overflow`，用例显式断言这一点，防止再把宿主 body 那一层滚动区拆掉）。

### 2. 默认模板的版本迁移（逐字段精确匹配；历史原文从 backups 源码抽取）

- `TEMPLATE_DEFAULT_VERSIONS` 是一张**记录在案的出厂默认表**：每一代默认（英文首发那代、
  中间的中文那代、当前这代）各带自己的 `version`。抽取方式是从工程 `backups/` 里那两版
  `plugin.js` 的源码中原样取出 `DEFAULT_TEMPLATES` 段（脚本落成 JS 字面量后写回源码），
  **不靠相似度、不靠记忆、不重打**。
- 升级的判据是**逐字段精确相等**（`sameTemplate` 比较 `system` 与 `user` 两个字段的完整文本）。
  任一字段被改过 → 整对**不升级**，原样保留；一对里只有一半是历史默认 → 也不升级，
  「猜」在这里就是覆盖用户内容的同义词。
- 每次写入都经唯一的写入路径 `commitTemplates`：它先把**被替换的那一对**放进**唯一一个**
  回退槽（`templates.previous.v1`），再写新值，最后落一条版本记录
  （`state` / `version` / `fromVersion` / `source` / `updatedAt`）。没有历史数据库，
  也不追加列表——只有一个槽。
- 「恢复默认」写的是当前代默认并记为 `state: default, version: <当前代>`；
  迁移写的是新默认并记下它替换掉的版本号。

### 3. 模板导入 / 导出 + 「恢复上一个版本」

**归档格式**（Python 侧 `fpe_templates.py`，纯 stdlib、无状态、无 I/O；两道后端门只负责读写文件）：

```json
{ "schema": "fragile-prompt-enhance.templates", "format_version": 1,
  "exported_at": "...", "plugin_version": "1.0.0", "template_version": 3,
  "scope": "both", "modes": { "precise": { "system": "…", "user": "…" } } }
```

- `scope` 是 `system` / `user` / `both`，**导入只应用归档自己带的那些字段**；
  纯 system 的归档不会碰到用户的 user 半。`template_version` 是信息，不是规则。
- 只含模板。**草稿、结果、历史、模型/供应商配置、凭据一律不在格式里**，
  而且顶层出现未知键、mode 里出现未知字段**都会被拒绝**（错误码 `unknown_key` /
  `unknown_field`）而不是被悄悄丢弃——「只保留认识的部分」正是「看起来应用了却没应用」的成因。
- 校验：先按**字节**上限（256 KiB）在解析前拦截，再逐字段查空、查长度上限（20000 字符）、
  查 `user` 是否仍带 `{{draft}}`。**一次报出所有**原因（不是只报第一条），
  UTF-8 BOM 接受但作为 warning 报出来。导入失败时**原样不动**。
- 预览 → 确认后才应用：`/templates/import/inspect` 只读并回答「会改成什么」，
  `importPreview()` 对每个字段同时给出**当前字数 → 导入字数**与
  **真实的逐行内容差异**（`previewFieldDiff`，复用对比视图那一个 `diffDrafts`，不另立一套
  「改动」定义）：`diff.rows` 带上最多 `PREVIEW_DIFF_ROWS`（8）条**改动行原文**（新增/移除各标一个
  前缀，前缀只在渲染时加、**不写进归档**），`added`/`removed` 是真实行数，超出部分用
  `transferImportDiffMore` 明说还剩几行**未列出**；字段整对相同则 `identical` 明说「完全一致」，
  不渲染差异块。**超过 diff 自身上限**（`DIFF_LIMITS`）的字段报 `ok: false` + `reason: 'too-large'`，
  界面直说「太长无法在此逐行比较」，**不**退回成「只报字数却看起来像预览」。
  确认走 `applyImportPreview()`，用**和编辑器同一个** `validateTemplatePair`
  再验一次（后端放行的坏对子在这里也进不去），然后经 `commitTemplates` 写入——
  于是被替换的那一对进回退槽，记录标为 `imported`（`import-file` / `import-paste`）。
- **导出走现役官方 SDK 的门，不发明接口**：`ctx.os.pickSavePath()` 返回的是
  **后端**文件系统上的路径（`apps/desktop/src/contrib/plugin.ts` 的注释原话就是
  「hand it to a `rest` call rather than trying to write it from the renderer」），
  所以渲染端**只挑路径**，写文件由后端那道门完成；渲染端不声称自己写了字节。
- **剪贴板是第二条、单独命名的通路**（`ctx.os.writeClipboard`）：按钮文案一个是
  「导出到文件…」、一个是「复制归档到剪贴板」，中英都不同名，避免把「复制」冒充成「导出文件」。
  取消保存、或这个宿主根本没有原生对话框（官方门两种情况都回 `null`），一律**明说没导出**，
  **不会**顺手复制一份了事；剪贴板拒绝写入则报错，不静默成功。
  **取消是原样**：不发请求、不写文件、不改模板，也**不碰剪贴板**——包括**不**清空剪贴板里用户
  原本就有的内容（有专门用例用预置的剪贴板内容锚这一条）。
- 文件导入失败与文档不可用是两种结果：前者 `reason: failed`（什么都没暂存），
  后者 `reason: invalid` 并把**每一条**原因留在界面上（不是一闪而过的 toast）。
- 「恢复上一个版本」是**换位**不是弹出：被换下来的那一对占据那唯一一个槽，
  所以撤错了还能撤回去。槽为空或内容不可用时拒绝，且界面文案区分「还没有上一版」与「留存自 …」。

### 1. 对比弹窗「完整原文」视图：两个 39px 横条

**症状**（用户第二张截图）：全文视图里原文块与增强稿块被压成约 39px 的横条，字被裁掉；
参考评分标题挤在原文框上，评分列左标签右分数对不齐（第一、三张高亮视图正常）。

**根因（源码级证据，不是猜）**：

- `DraftPanel` 的文本盒是 `flex-1 overflow-auto`，父级链（`.flex.min-h-0.flex-col.gap-3` →
  `.flex.min-h-0.gap-3`）**没有一个是定高**。`flex-1` 是 `flex: 1 1 0%`，在自动高度祖先里
  basis 解成 0 → 盒子只剩自身 padding 的高度，`overflow-auto` 再把其余内容藏起来。
  这就是那条 39px 横条：**不是少了样式，是一条 CSS 在错误的容器里。**
- 宿主 `apps/desktop/src/components/ui/dialog.tsx` 的 body 已经是**唯一**的滚动区
  （`grid min-h-0 grid-cols-[minmax(0,1fr)] … overflow-y-auto`，外层 shell 是
  `fixed … max-h-[85vh] flex-col`）。插件又在 body 内部造了第二个滚动区，两边都不好使。
- 弹窗宽度：宿主 shell 自带 `w-full max-w-lg`（32rem）。插件加的是 `max-w-4xl` —— 实测
  **宿主 bundle 里根本没有 `.max-w-4xl` 规则**（`apps/desktop/dist/assets/index-*.css`），
  于是弹窗一直 512px 宽，两列全文被挤成竖条。
- 评分区是从头单列的 `justify-between` 行，每行的中缝跟着该行文字跑，所以永远对不齐。
- 顺带查出一条同类死类：评分单元格上的 `align-bottom` 在宿主 bundle 里**没有编译出规则**
  （宿主源码没有任何地方用它），一直在白写。

**修法**：

- 全文块**不再自带高度与滚动**：去掉 `flex-1` / `min-h-0` / `overflow-auto`，改成
  `min-h-24`（6rem 可读下限）+ `whitespace-pre-wrap` + `break-words`。高度由内容决定，
  滚动交给宿主 body **一处**。
- 弹窗宽度改用 **`min-w-[min(48rem,90vw)]`**：`min-width` 与 `max-width` 相遇时 min-width 赢，
  不受规则顺序影响；90vw 保证小屏不出界。这个类**正是宿主自己的宽弹窗在用的**
  （`apps/desktop/src/app/capabilities/connectors/add-dialog.tsx:82`），所以一定编译得出来。
- 评分改成**真正的 `<table>`**：一行表头 + 五维 + 总评，每行固定三列（标签 / 原文 / 增强稿），
  数值列 `text-right tabular-nums`；颜色**只用宿主既有 token**（`--ui-bg-secondary`、
  `--ui-stroke-secondary`、`--ui-text-*`），不引入任何新色值，玻璃主题不受影响。
- 全文块默认**不设高度上限**，长文/缩小屏都能读；评分独立成块（`Separator` 之后）。

### 2. 「0 精确项」的误导文案

`protectionOk(0)` 渲染成「0 项精确内容全部保留」，读起来像一次通过的检查；实际上只是草稿里
没有代码块 / 路径 / URL / 引用标识可核对。新增两个语言的 `compare.protectionNone`：

- zh：「未检测到需逐字保护内容，因此没有需要逐条核对的项目。」
- en：`No content needing verbatim protection was detected, so there was nothing to verify.`

渲染时 `total === 0` 走 `data-fpe="protection-none"`，非零才走 `protection-ok` —— 两条事实
在**缝隙**上就分开了，读的人不必解析句子。

### 3. 专用模型思考等级：**能力不存在，明确阻断**（纠正上一轮的做法）

用户反馈「思考等级锁死」。追下去有两层，**上一层查清了，下一层上一轮做错了**。

**第一层（事实，已核验）**：插件可用的两扇官方 LLM 门都不带 reasoning 参数。

- `agent/plugin_llm.py`：`PluginLlm.complete` / `acomplete` / `complete_structured` /
  `acomplete_structured` 的参数是 `provider` / `model` / `temperature` / `max_tokens` /
  `timeout` / `agent_id` / `profile` / `purpose` / `task` —— **没有任何 reasoning 参数**；
  `_host_kwargs` 也是从这个封闭集合拼 `call_llm` 的入参，所以连 `auxiliary_client.call_llm`
  确实接受、但不在集合里的 `reasoning_config` 也**到不了**。
- `tui_gateway/contracts/sessions.py`：`LlmOneshotParams` 只有 `template`/`instructions`/
  `input`/`variables`/`task`/`temperature`/`max_tokens`/`session_id`，handler 也不转发任何等级。

**第二层（这一轮补查的：能不能把控件藏掉）**：`ModelCatalogMenu` 的**全部** props 是

```
controller · footer · gateway · includeMoa · ownerConnectionId · profile · request · sessionId
```

`sdk/index.ts:1703` 导出它，但 props 里**没有任何一项**能隐藏或禁用思考子菜单：
子菜单是菜单自己**无条件**渲染的（`model-catalog-menu.tsx:650` 的 `<ModelEditSubmenu …/>`），
而它那些行由**回传给它的目录数据**决定（`reasoning={caps?.reasoning ?? true}`、
`canDisableReasoning={caps?.can_disable_reasoning}`），不由调用方决定。
`model-edit-submenu.tsx:93` 的 `reasoning: boolean` 就是那个门 —— 它是 catalog 的能力字段。

也被考虑并**否决**的两条路：改写 `request` prop 返回的目录去把 `reasoning` 抹成 false，
是在**谎报模型能力**（避开的是插件的边界，改的是模型的事实），而且等级照样传不出去；
用 CSS 或探测宿主 DOM 去藏控件，更不允许。

**结论：等级既发不出去，也藏不掉。** 唯一不能做的就是第三件事——**收下这个选择、存起来、
让用户以为它生效了**。上一轮正是这么做的（`setOptions` 真写 `settings.pinnedEffort`），
所以这一轮改成：

- `EFFORT_TRANSPORT` 记下**两次核查**：`supported: false`（两扇门都不带参数）、
  `catalogMenuProps` 逐项列出菜单的 prop 面 + `catalogMenuHidesEffort: false`（没有一项能藏子菜单）。
  宿主哪天给门上加了参数、或给菜单加了控制 prop，对应断言会**先红**。
- `setOptions` **拒绝**：不写 `settings`、不 `persistSettings`、不 `patch`，而是
  `notify('warn', …)` 用一句本地化的话说明「不会应用……既不会被保存，也不会被发送」。
  **不是静默 noop**：用户会看到一条通知，而不是一个动过却什么都没发生的单选钮。
- `applyPreset` 只应用**模型**：目录在每次选中时都会回传 `preset.effort`（它拿 profile 默认值填），
  这个值**也不落盘** —— 存一个不会生效的等级和假控件是同一种谎话。
- `current.effort` 与 `presetFor()` 一律报 **`''`**：**不再把已存的等级回报给目录**。
  回报就会点亮那颗单选钮与该行的等级徽标，等于把一个失效的值画成「已选中」。
- 面板不再显示「已记录的值」，改为**直说本构建不提供**；`settings.pinnedEffort` 里若还留着
  旧版写入的值，会**点名**显示为「仍留着此前版本记录的值：high。它不会被应用。」——
  既不假装它是当前选择，也不悄悄删掉用户的数据。
- `applyEffort()` 与 `applyModelSelection` 的 `effort` 形参**一并删除**：没有任何写入口，
  就不留一条将来会被误接回去的死路。`normalizeEffort` 保留为**只读**归一化（读旧值、拒绝陌生值）。
- **请求体里不出现任何 effort/reasoning 字段**（有专门用例断言）：一条会被后端忽略的字段
  就是同一句谎话。
- 等级刻度仍**照抄宿主**（`apps/shared/src/reasoning-effort.ts`），测试直接读宿主源码逐值比对。
- **没有**预埋未来功能：没有 `if (supported) { … }` 分支、没有隐藏开关、没有「等宿主支持就自动打开」
  的预留代码。契约变了是先让测试红，再由人决定要不要实现。

### `test_fpe_parsing.py` — 解析与评分归一化

核心契约：**评分缺失、为空、非法 JSON、结构不符时，正文绝不丢失**。

- 四类评分失败（`empty` / `unparseable` / `unrecognized` / `absent`）分别对应稳定的 `score_error`，
  正文照常返回。
- 0-100 **越界被拒绝，不是夹取**（`_coerce_score` 对 105 / -1 返回 `None` 并记入 `issues`，
  绝不把 105 悄悄改成 100 —— 那会呈现模型从未给出的数字）；非数字丢弃；五维与总评各自独立。
- 代码围栏里的 JSON、正文里出现的 `SCORES` 字样不会误判为评分块。
- 标签行（`Enhanced prompt:` 单独成行）被剥离；正文中间的同名文本不被剥离。

### `test_fpe_protect.py` — 精确内容保护

- 代码块、路径、URL、`#123` 引用按优先级提取，互不重复计数（代码块里的路径只算一次）。
- 丢失 → `missing`；仅空白/换行变化 → `altered_whitespace`（不阻止回填但会提示）。

### `test_plugin_api.py` — 薄后端路由 + ctx 桥

### `test_plugin_desktop.mjs` — desktop 半

i18n：

- `en` / `zh` key 集合**完全一致**；
- **没有任何字符串叶子残留 `{...}` 占位符**（唯一允许的是说明模板用的 `{{draft}}`）——这条专拦
  「带参数文案写成字符串」这个 SDK 契约错误；
- 12 处带参数文案在两个语言包里都是函数，且调用后真的替换了参数、不留大括号；
- `zh` → 中文、`en` → 英文、未提供语言包的 locale → 英文包 → 键名；
- 覆盖按钮/菜单/设置各页/五维/免责声明/错误码/进度/空状态；
- 源码里所有字面量 key 在两个语言包都存在（动态家族另有专项用例）；
- 插件不持久化任何语言设置，也不使用私有的语言机制。

运行期：

- **停止丢弃迟到结果**：等 `/enhance` 真的发出后停止，再放行响应 → `discarded`，`setDraft` 一次都没调，
  也不弹成功提示。
- 运行中用户改了草稿 → `draftChanged`，**不覆盖**，结果留在对比视图。
- 精确内容丢失 → `blocked`，不回填。
- 成功 → 回填并武装单级撤销；**默认不打开对比视图**（`showCompareOnSuccess` 默认 `false`），
  结果仍留在内存里供手动对比；撤销一次后第二次 `no-undo`。
- 回填后手改草稿 → 撤销被阻止（`undoMismatch`）。
- 无挂载输入框导致写入失败 → `applyFailed` 且报错，不谎称成功。
- 模型：
  - **跟随会话**走官方无状态 RPC `llm.oneshot` 且**必带 `session_id`**——真实借用该会话的
    `main_runtime`，不写入会话历史；正文由 `/prepare` 渲染、由 `/parse` 解析，正文只发一次；
  - **没有活跃会话**（`new` 空草稿）→ 明确走全局模型（`/enhance`，即 `ctx.llm` 的 profile 全局绑定），
    并明确提示这是全局模型，**不创建会话**来伪造 `session_id`；
  - **固定模型**发真值走 `/enhance`；**信任门关闭时本地直接拒绝（没有 body）**，绝不静默降级。
  - **按 (connectionId, profile) 路由**：owner 属于别的连接时必须有路由描述符，否则**拒绝**
    而不是误发到当前连接；`'local'` 与 `null` 按官方语义视为同一台机器。
- 失败语义按真实传输层归类，不再一律 `network`：
  - 有 `statusCode`（官方 `httpStatusError` 形状）→ 读状态码与后端自己的 `error.code`
    （403 授权/未授权、504 超时、502 上游、429 限流、404 路由未挂载…）；
  - 无 `statusCode` → 传输层：`AbortError`/超时 → 超时；bridge/gateway 不可用 → 网关；其余才是网络。
  - gateway RPC 另按 JSON-RPC `code` 归类（`-32601` 无此方法、`4030/4031/4032` 被拒、`5030` 生成失败），
    **不伪装成 HTTP 状态**。
- 诊断只存内存；`STORAGE_KEYS` 之外没有任何 `storage.set`。
- 语言包 key **就是**官方 `Locale` 宏（`en` / `zh`）——`zh-CN` / `zh-Hans` 永远解析不到，
  会让简中界面静默显示英文。
- **模型选择是一道明确的二选一**，不是「跟随会话」开关：
  - `MODEL_CHOICES` 只有 `session` / `pinned` 两项，`modelChoiceValue()` 返回的值**就是写回
    `settings.modelMode` 的那个值**——标签与状态不可能再读反（旧版 `checked` 绑的是
    `modelMode === 'pinned'`，而标签写的是「跟随会话」，方向是反的）；
  - **无论授权与否都能看目录并选择**：`modelPanelState()` 的 `showCatalog` 只取决于当前模式，
    不再与信任门做 AND。授权是**独立的另一行**（`model-grant-open` / `model-grant-closed`），
    与选择器并列而不是替换它；
  - **选择只改插件设置**：面板只写 `settings`（`STORAGE_KEYS.settings`），不碰会话模型、
    不碰 `config.yaml`、不调任何授权接口。
- **未授权时按模型名硬拒绝**：`planRun` 在发起请求之前就返回 `status.capabilityBlocked` 并带上
  被拒的模型名，**不静默降级**为会话模型，也不改任何设置。
- `templates.v1` 迁移：只有**精确等于**旧版示例对的存量才被替换为新中文默认；用户改过的、
  以及只部分匹配的**一律原样保留**（不做猜测性迁移）；`register()` 迁移后会写回并记
  `templates.meta.v1`；「恢复默认」给出的是**新版**默认而不是旧版。
- 出厂的默认模板必须是**两模式完整中文对**，且带来源方法（解构→重构→复核）、带上
  「保留草稿语言」规则、带精确内容保护；不得退回两句泛化英文，不得带角色头衔或字数配额。
- **版本记录（本轮）**：`templateMeta()` 的 `version` 永远由**字节**经 `defaultVersionOf()` 判定，
  不由上一次写入留下的记录决定；**首次运行**（从未写过 `templates.v1`）也会在启动时把记录落定为
  当前默认版本（`state: default`），此后启动不再改写（记录与字节一致时不写）。
- **导出 `template_version` 永不为 `null`（本轮）**：未定制的安装导出**整数**（`TEMPLATE_VERSION`）；
  自定义内容导出显式 `'custom'` 标记；任何「不是出厂默认」的字节都**不会**被贴上某个版本号。
- **归档的声明不写进记录（本轮）**：导入一份声称某版本、字节其实是另一版本的归档时，
  记录与之后的导出都取**字节**的判定结果；归档的声明只作为预览信息。
- 导出的版本经「导出 → 读回 → 再导出」一轮往返不退化回 `null`。

### `tests/test_template_transfer.py` — 模板归档格式 + 后端两道门（49 条）

`fpe_templates` 是**纯函数**格式层（构建/序列化/校验/摘要，无 I/O、不 import Hermes），
`/templates/export` 与 `/templates/import/inspect` 是它的两道门：
